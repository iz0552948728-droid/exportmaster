# Export Master

МАСТЕР ЭКСПОРТА РЕЗУЛЬТАТОВ ИЗМЕРЕНИЙ — модуль форматирования.

Сливает markdown-шаблон с результатами измерений из файла многомерной матрицы
(`.mtx`) и сохраняет результат в формате, принятом у заказчика. Работает в режиме
командной строки; диалоговый режим появится отдельным этапом.

## Что нужно для работы

.NET 8 SDK. В Visual Studio 2022 — рабочая нагрузка «Разработка классических
приложений .NET»; отдельной установки SDK не требуется.

```bash
dotnet build
dotnet test
```

259 тестов, все должны быть зелёными. Если их заметно меньше — часть проектов
не загрузилась: закройте решение, удалите папку `.vs` и откройте заново.

## Запуск

```bash
ExportMaster.Formatter.Cli /source samples/data/aaa-1.5.mtx \
                           /md samples/templates/example2.md \
                           /target out /id 42
```

| Ключ | Назначение |
|---|---|
| `/source <файл>` | файл данных; без него подставляются заглушки |
| `/md <файл>` | файл шаблона |
| `/target <путь>` | каталог для результата |
| `/id <идентификатор>` | идентификатор задания, попадает в протокол |
| `/key <ключ>` | принимается, но отбор по нему пока не выполняется |
| `/overwrite yes\|no` | перезаписывать существующий файл, по умолчанию `yes` |
| `/stub descriptive\|sample` | вид заглушек, отладочный ключ вне ТЗ |

В Visual Studio готовые профили запуска лежат в `ExportMaster.Formatter.Cli`:
«Настоящие данные», «Пример: заглушки-описания», «Справка по ключам».

Стандартный вывод — только протокол из п. 4.3.3 ТЗ, по строке на файл. Диагностика
идёт в stderr и в журнал (папка `LOGS` рядом с исполняемым файлом, хранение 10 дней).
Коды возврата: `0` — все файлы сформированы, `1` — частично, `2` — задание не выполнено.

## Раскладка решения

| Проект | Назначение |
|---|---|
| `ExportMaster.Core` | перечисление измерений `Dimensions` — общий словарь |
| `ExportMaster.Formats` | чтение `.mtx`: метаданные, блок заголовка, описатели, матрица |
| `ExportMaster.Template` | лексер и парсер шаблона в дерево |
| `ExportMaster.Engine` | вычисление полей, рендер, разбиение, формирование файлов |
| `ExportMaster.Formatter.Cli` | командная строка, протокол вывода, журнал |

Зависимости строго вниз: `Cli` → `Engine` → `Template` / `Formats` → `Core`.
У каждого проекта свой проект тестов в `tests/`.

## Состояние

Готово: чтение `.mtx` обеих раскладок описателя, блок заголовка целиком, разбиение
по `GROUPBY`, табличная подстановка, поля заголовка (`FIELD`), форматирование,
кодировки, журнал.

Не сделано: поля `NAME` и `CALC` из таблицы ТЗ п. 4.4.3.3 (состав функций не
согласован), отбор по ключу `/key`, единый конфигурационный файл (п. 4.1.3),
диалоговый режим.
