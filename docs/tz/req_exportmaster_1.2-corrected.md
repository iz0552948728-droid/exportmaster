### 4.4. Требования к маркдаун-файлу

4.4.1. Маркдаун-файл состоит из заголовка и тела, заголовок отделяется служебными символами и не попадает в результирующий файл. Заголовок открывается строкой [MDHEADER] и закрывается строкой [/MDHEADER].

4.4.2. Заголовок маркдаун-файла содержит информацию о способе формирования имени файла и о способе отбора данных из многомерной матрицы.

4.4.3. Специальные поля в теле маркдаун-файла могут быть следующих видов:

* поле прямой подстановки;

* вычислительное поле;

* поле формирования таблицы.

4.4.3.1. Специальное поле представляет собою набор кодовых слов, заключенный в фигурные скобки "{}". Если требуется вывести в результирующий файл фигурные скобки, то они записываются как "{{" и "}}".

4.4.4.2. Специальное поле внутри специального поля расшифровывается как специальное поле и включается в синтаксис поля, внутри которого оно находится.

4.4.3.3. Синтаксис полей и описания:

| Тип поля                                 | Базовый синтакис |
| ---------------------------------------- | ---------------- |
| Прямая подстановка поля из заголовка     | {FIELD(<имя поля>)}, имя поля берётся из таблицы п. 4.2.1.6, регистр не учитывается
| Прямая подстановка имени из матрицы      | {NAME(значения ключа...)}
| Прямая подстановка значения из матрицы   | {VALUE(значения ключа...)}
| Вычислительное поле                      | {CALC(ИМЯ_ФУНКЦИИ[,параметры])}
| Применение встроенной функции к значению | {ИМЯ_ФУНКЦИИ(значение[,значение...])}, в качестве значения обычно выступает какая-то еще подстановка
| Форматирование значения                  | {FORMAT(формат, значение)}, в качестве значения обычно выступает какая-то еще подстановка

| Текст | Пояснение

| {FORMAT("#.00 дБм",{FIELD("P")})} | Отформатировать поле мощности из заголовка в дбэмы, 2 знака после запятой

4.4.4. Способ формирования имени файла, находящийся в заголовке маркдаун-файла, представляет собою специальное поле {FILENAME(любые значения)}

4.4.5. Способ отбора данных, находящийся в заголовке маркдаун-файла, представляет собою список типов полей согласно 3.1 из п.4.2.1.2., по котороым производится итерирование, а порядок полей в списке определяет порядок итерирования. Например, список отбора данных вида POL1,FREQ,CHANNEL,BEAM говорит о том, что результирующие файлы необходимо формировать для каждой уникальной комбинации поляризации зонда,частоты,канала и луча. Это аналог выражения GROUP BY из SQL.

4.4.6. Для каждого формируемого выходного файла согласно способу отбора данных, у нас получается многомерная матрица уменьшенной размерности (возможно даже 1х1), которая является исходными данными для табличной подстановки.

4.4.7. Табличная подставновка имеет следующий синтаксис:

{TABLE(<заголовки колонок>,<заголовки строк>,<функция данных>,формат,<разделитель ячеек>)}

Допустим, у нас сечение по 2м поляризациям. Отбор данных может выглядеть так: P1 (отбираются 2-мерные данные (частота и позиция) для каждой поляризации), тогда описатель таблицы может выглядеть так:

{TABLE("FREQ","DATA","AMP","0.00",";")}, что означает:

в колонках частоты, в строках позиции по оси сбора данных, в ячейках пишется амплитуда, формат вывода 2 знака после запятой, ячейки разделяются точкой с запятой

При этом будут сформированы два файла (для 1й и 2й поляризации), каждый со своим набором данных.
